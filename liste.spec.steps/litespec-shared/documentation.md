# Living documentation

Before archiving, assess impact. Keep durable knowledge in project-relative `.litespec/docs/index.md` and topic notes; link authoritative detail. If no update is needed, record why in spec.md; create no empty notes/index. Obsidian means Markdown/relative links, not external vault setup; another destination requires explicit user direction.

Gather the `Docs:` lines from spec.md and steps instead of rereading whole steps or diffs; read sources only to fill a concrete gap or check a doubtful fact. For steps without the line, assess from their evidence. Group facts by topic and write each topic once.

Read only the index and affected topics. Index each with a link and one-line purpose. Document verified behavior/purpose, final decisions/reasons, key paths/symbols/roles, and constraints; omit obvious detail and task lists. Keep one small note per stable topic, not per spec; split only for separate reading. Replace stale facts; update other affected maintained docs. Keep docs outside archives; preserve archived history and link superseded specs. Record unavailable required updates as pending.
