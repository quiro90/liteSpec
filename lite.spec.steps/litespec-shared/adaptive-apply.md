# Execute adaptive steps

The parent owns status, integration and records. Execute principal-owned steps directly. If the effective worker model matches the principal and isolation adds no value, execute directly and record it. Role delegation may assist research and planning independently.

For an authorized executor-owned step with satisfied prerequisites, use `litespec-very-easy` for `very-easy | executor` in Codex or Claude Code and `litespec-easy` for `easy | executor`. Other difficulties stay with the principal. If the required worker is unavailable, follow the direct execution fallback below.

Record the owner and attempt in the continuation note before dispatch. Invoke the selected profile once in a fresh context. Send the step path, the installed [worker instructions](easy-worker.md), and only shared constraints or acceptance details missing from the step. Save the native handle if available. Wait for a result or blocker through native notification/wait and avoid polling, duplicate work and transcripts.

For a diagnosed in-scope defect, record and allow one correction across sessions, preferably with the same worker. A changed premise goes to the principal for revision. After interruption use Apply's active-step recovery before further edits. If delegation is unavailable and no worker is running, report once and continue directly within authorization and user budget. Never infer actual model use from a profile.

When implementation ends, before verification, record `Executed: executor | principal | executor-then-principal; corrections: <n>`. A principal result on an executor-owned step means the worker never started; `executor-then-principal` means the principal finished partial worker output. Keep that line when replacing continuation details with acceptance evidence.
