# Incremental revision

Use when user decisions change or sources differ from recorded findings. Archives are immutable: start a linked change through Explore.

1. Read spec.md, the current/affected step, and relevant deltas using recorded paths/symbols and targeted searches. Expand only for missing details or changed dependency contracts.
2. Apply shared agreement rules. Resolve technical adjustments within agreed behavior and authorization. Preserve user edits; ask unresolved scope, behavior, acceptance, or edit-conflict questions. Pause affected work awaiting answers; continue independent authorized work.
3. When rewriting specs, read the [specification contract](specification.md). Replace stale decisions, context, tasks, acceptance, and prerequisite interfaces. Retain agreements/authorizations only where they cover revised scope, continuity, and closure. In Adaptive, split and reclassify affected remaining work under [adaptive planning](adaptive-plan.md). Add/remove steps as needed; keep dependencies acyclic. Follow invalidated dependents, including done steps; stop at unchanged contracts.
4. Reopen affected done steps as pending (blocked awaiting answers); invalidate only affected checkboxes, evidence and `Docs:` lines. Preserve other progress. Keep implementing once execution begins; otherwise draft while material questions remain, ready when specified. Record blockers and next actions, not revision logs. Recheck affected acceptance/integration before closure. Keep explicit documentation deliverables current; consolidate living docs through litespec-archive. Spec edits do not authorize implementation.
