# Documentation and closure

**Living docs:** assess impact before archiving. Store durable knowledge in `.litespec/docs/index.md` and topic notes; link authoritative detail. If no update is needed, record why in spec.md; create no empty notes/index. Paths are project-relative. Obsidian compatibility means Markdown/relative links, not an external vault or vault setup; alternate destinations require explicit user direction.

Index topics with links and one-line purposes. Read only the index and affected topics. Document verified behavior/purpose, final decisions and non-obvious reasons, key paths/symbols and roles, and constraints. Reuse stable topics, not per-spec notes; split only for separate reading. Replace stale facts; omit task lists and obvious code detail. Keep docs outside archives; update other affected maintained docs. Preserve archived history, link superseded specs, and record unavailable required updates as pending.

1. Follow [verification](verification.md) for the whole change; require all steps done and no required work pending. Remove explicitly dropped tasks or record exclusions; never mark unperformed work complete.
2. Check required docs, affected index links, and content against verified results. Record paths/result or no-update reason in spec.md. Missing required docs block closure.
3. Summarize outcome, checks, docs, and limitations. Require explicit archive authorization covering completed scope; reuse valid authorization. Implementation permission is insufficient. If missing, ask after verification and wait; approval cannot replace checks.
4. While blocked, record one closure field in spec.md: `pending-verification`, or `pending-confirmation` once verified, with missing item/next action. Report blockers without duplicating task lists. Once verified and authorized, record both and move the whole folder from `.litespec/specs/<spec-name>/` to `.litespec/archived/<YYMMddHHmm>-<spec-name>/` using local closure time. Never overwrite or retain an active copy. Adjust affected relative links and check them after moving. Mark done only after successful closure; on failure, record/report incomplete closure and next action. Report docs/archive paths. Later changes need a new spec.
