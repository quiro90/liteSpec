# Documentation and closure

**Living documentation:** before archiving, create or update `.litespec/docs/index.md` and small topic notes in `.litespec/docs/`. Paths are relative to the project root. Obsidian compatibility means Markdown and relative links, not an external vault or vault configuration; an alternate destination requires explicit user direction. Index each topic with a link and one-line purpose. Read only the index and affected topics; document verified current behavior, purpose, final decisions with non-obvious reasons, key paths/symbols and their roles, and necessary constraints. Reuse notes by stable topic, not by spec; split only when topics warrant separate reading. Replace obsolete facts; omit task lists and obvious code details. Keep docs outside archived change folders. Update other affected maintained documentation; link rather than duplicate authoritative detail. Preserve archived history and link superseded specs. Record unavailable required updates as pending.

1. Verify no required tasks remain unchecked, all steps are done, and overall acceptance, integration, continuity/compatibility, and required checks pass. Reuse still-valid recorded results; inspect task status and evidence, not only step labels. Unrun or unavailable checks remain pending. Remove tasks explicitly dropped from scope or briefly record their exclusion; never mark unperformed work completed.
2. Verify the documentation index exists, affected topic links resolve, and notes reflect the verified result. Accurate notes need no rewrite. Record checked documentation paths and a brief result in spec.md; missing required docs block closure.
3. Present a concise outcome/checks/docs summary and any limitations. Archive only with explicit user authorization covering the completed scope; reuse valid prior authorization, but implementation permission alone is insufficient. If missing, ask after verification and wait. Approval never substitutes for required checks.
4. While blocked, keep the change open and record a single closure field in spec.md: `pending-verification` or, once verified, `pending-confirmation`, plus only the missing item and next action. Report what prevents closure; do not duplicate task lists. After both gates pass, record overall verification and archive authorization, and move the whole change folder from `.litespec/specs/<spec-name>/` to `.litespec/archived/<YYMMddHHmm>-<spec-name>/` using local closure time. Overwrite nothing; leave no active copy. Adjust affected relative links and verify they resolve after the move. Mark done only on successful closure; if moving fails, record/report incomplete closure and next action. Report documentation and archive paths at completion. Later changes get a new spec.
