# Incremental revision

Use this procedure when the user changes an active change or relevant files differ from recorded findings; speclite-modify is its explicit entry point. Archived changes stay immutable: create a linked new change through Explore.

1. Read spec.md, the current or directly affected step, and only the requested delta or relevant changed source sections. Use recorded paths/symbols and targeted searches; do not reload all steps, docs, or project files. Expand only to resolve a concrete missing detail or a changed dependency contract.
2. A clear user decision updates the agreement without repeat confirmation; a suggestion is not a decision, and an edited file is not proof of user intent. Resolve technical adjustments within agreed behavior and authorization. Ask only unresolved material questions about scope, behavior, acceptance, or conflicting edits; preserve user edits and pause affected work until answered. Continue independent authorized work.
3. When rewriting specification content, read the [specification contract](specification.md). Replace obsolete decisions, context, tasks, acceptance, and prerequisite interfaces in spec.md and affected steps; preserve valid agreements and authorizations only where they cover the revised scope, including continuity and closure. Add or remove steps only as needed and keep prerequisites acyclic. Follow dependents only where their assumptions or checks are invalidated, including already completed steps; stop propagation at unchanged contracts.
4. Reopen affected done steps as pending (blocked if awaiting an answer); invalidate only affected checkboxes and verification results. Preserve unaffected progress. Keep implementing if execution has begun, recording unresolved questions as blockers; otherwise use draft while material questions remain, ready when specified. Record only remaining work/blocker and next action, not a revision log. Recheck affected acceptance and integration before closure; update affected maintained docs when their behavior is verified, reading [documentation rules](closure.md) when maintaining living docs. Updating a spec alone does not authorize implementation.
